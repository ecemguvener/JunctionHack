# Data and training workbench

The workbench builds local HTML reviews and JSON readiness reports. It uses the existing core Python environment (NumPy, Pillow, PyYAML and the standard library); no web framework, training environment, robot, cloud account or camera is needed to review data. Pages contain embedded image previews and work offline. They do not upload data or execute the displayed commands.

## Fresh checkout: reproduce the complete review workflow

Install Git and uv first. From a new checkout:

```bash
git clone --branch codex/data-training-workbench https://github.com/ecemguvener/JunctionHack.git
cd JunctionHack
uv python install 3.12
uv sync --locked
uv run pytest

# Tiny, explicitly labeled FORMAT fixtures; this does not simulate a successful grasp.
uv run python -m brickcell.workbench demo --output data/workbench-example

# Import labeled images; original images remain untouched.
uv run python -m brickcell.workbench import-inspection \
  --csv data/workbench-example/inspection/capture.csv \
  --output data/workbench-example/inspection/imported.json
uv run python -m brickcell.workbench inspection \
  --manifest data/workbench-example/inspection/imported.json \
  --output artifacts/workbench/example-inspection --strict

uv run python -m brickcell.workbench policy \
  --manifest data/workbench-example/policy/manifest.json \
  --limits configs/workbench-sim-limits.json \
  --output artifacts/workbench/example-policy --strict

# Optional localhost serving; opening each index.html directly also works.
uv run python -m http.server 19092 --bind 127.0.0.1 --directory artifacts/workbench
```

Open [inspection review](http://127.0.0.1:19092/example-inspection/) and [demonstration review](http://127.0.0.1:19092/example-policy/). Use the episode selector, Play/Pause, Previous/Next, frame slider and joint selector. Both camera images and the joint table share the selected frame index. The plot compares measured state with commanded targets, not actual versus predicted defect probabilities. In inspection review, filter by label, face and split. The example only records `front`; selecting `top` must show zero images. Missing faces are listed by object and session.

Output paths must be fresh. To repeat a review, use a new `--output` directory. To revisit an existing report, open it without rerunning generation. Existing data, reports and model directories are never overwritten by these commands. Reports are snapshots; regenerate to review changed source files. Generated files stay under ignored `data/` and `artifacts/` directories. HTML embeds image data and local paths: share only with approved dataset recipients, not in Git.

Exit codes: 0 means the review was generated; `--strict` changes this to 1 if smoke readiness fails; 2 means malformed inputs or an operational error. A successful report generation without `--strict` is not a readiness pass.

## Inspection import contract

Copy `configs/workbench-capture-template.csv` into your image dataset directory and fill one row per image. Required columns:

| Column | Meaning |
|---|---|
| `path` | Image path relative to the CSV location; spaces supported |
| `object_id` | Stable ID of the physical brick; retain it before/after applying a mark |
| `family`, `color` | Shape family and color, e.g. square/red or long_narrow/white |
| `session_id` | Capture session ID; start a new one after changing camera/lighting setup |
| `face` | `front`, `right`, `back`, `left`, `top`; top means the studded face in object coordinates |
| `label` | `good` or `defective` for the visible face, not an invisible defect elsewhere |
| `split` | `unsplit` for initial collection, or frozen `train`, `val`, `test` |
| `synthetic` | Literal `true` or `false` |
| `defect_type` | Required for defective images, e.g. `marker_marks` or `surface_contamination`; blank for good |

The importer checks images, metadata, duplicate paths/content, normal-only training, and object/session overlap before publishing a manifest. It computes stable content-derived image IDs. Family and color are optional additions to the existing manifest schema; old manifests remain loadable. Existing splitting and model training preserve/use the same manifests.

```bash
uv run python -m brickcell.workbench import-inspection \
  --csv data/station/capture.csv --output data/station/capture.json
uv run python -m brickcell.workbench inspection \
  --manifest data/station/capture.json --output artifacts/workbench/station-capture

# Once independent collection groups exist; inspect the assignments before training.
uv run python -m brickcell split-data \
  --manifest data/station/capture.json --output data/station/split.json
uv run python -m brickcell.workbench inspection \
  --manifest data/station/split.json --output artifacts/workbench/station-split --strict
```

Object and session grouping both apply. A single session containing every brick connects them all: it cannot be divided without leakage under this conservative splitter. Plan independent train/calibration/test sessions with disjoint physical objects. Rephotographing a training brick after marking it does not make it an independent test object. The splitter needs at least three independent all-good groups and two defect-containing groups; these are software minimums, not sufficient sample sizes for performance claims. Keep the final test partition fixed and unused for threshold/model selection.

Every inspection report includes a concrete `patchcore-review.yaml` and exact train/export/parity/evaluate commands using the selected manifest and a fresh model output directory. Training may download the official pretrained backbone on first use. Commands are not launched by the page. `smoke_ready` checks the existing trainer's partition/class and image integrity requirements; it does not claim five-face coverage or sufficient diversity. Missing metadata and five-face label completeness are reported separately. Face labels are human assertions, not automatic occlusion verification.

## Demonstration contract and readiness

Currently supported input is the existing Brickcell NPZ + JSON episode format, **not a direct LeRobot/Studio import**. Preserve raw station recordings in their native format. A conversion adapter must be tested against the station's pinned version before those recordings can use this viewer. Do not rename a LeRobot directory to make it look compatible.

Each archive contains:

- `timestamp`: N finite seconds, uniformly spaced at the declared positive `fps` (the existing loader uses 1e-6-second tolerance).
- `overview`, `wrist`: N × 128 × 128 × 3 RGB uint8 frames.
- `state`, `action`: N × 6 finite joint values in the exact order declared by `brickcell.policy.data.JOINTS`. The current archive contract uses radians, including the simulated gripper joint. Physical gripper opening percentages must not be relabeled as radians.
- Actions are absolute joint targets associated with the observation **before** the corresponding step. No guessed resampling or padding is performed.

The JSON declares version, units, joint/camera order, timing semantics, synthetic status, teacher/source, FPS, and episode paths/IDs/hashes/frame counts/success/splits/seeds. Real episodes additionally need physical object and session IDs. Checks include actual trainer-loader compatibility, duplicate IDs/hashes/seeds, object/session split leakage, missing/corrupt archives, missing/misaligned camera frames, timestamps, finite values and both state/action bounds. A matching limit profile is mandatory for readiness. Simulation profiles are refused for real recordings. A `physical_measured` profile must describe the same coordinate system as the converted dataset; its provenance and conversion still require operator verification.

The report retains frame indices for every limit violation and highlights affected joint cells in red. No samples are clipped. Declared equal frame indices do not prove real cameras were synchronized: sensor timestamp and exposure checks remain a station task. Failed episodes may be reviewed, but the existing successful-teacher trainer rejects them.

For a reviewed, ready dataset, the report prints a command using the isolated policy environment and an explicit dataset path. Review the generated command before running it. The tiny generated FORMAT fixture can test the loader/optimizer only; use reviewed robot trajectories to learn movement. A green readiness badge is not trained-policy success, enough demonstrations, or approval to operate hardware.

## Returning to the station

Follow [STATION_COLLECTION.md](STATION_COLLECTION.md) before scaling collection. This workbench does not start teleoperation, access serial ports, change calibration or connect to the Intel server.

The simulation panel now identifies synthetic camera images and scripted IK above the run controls. Its Connected indicator is explicitly explained as the local viewer connection. Each pick/reset clears old inspection results; a capture reports one fixed camera view and **0/5 confirmed named faces**. Until named presentations and visibility checks exist, the single-view GOOD decision must not be used as proof of complete five-face inspection.
